# 원고 기능 설계 (Athenaeum 작성 모듈)

2026-09-04 합의. **범위: 아이디어 검토 → 근거 정리 → 개요 → 문단 초안 → .docx 내보내기.**
서식·그림 배치·공저자 교정은 워드에서 한다. 초안이 워드로 넘어간 뒤에는 워드가 원본이고, 아테네움은 근거를 찾아보는 참고 창이 된다.

## 왜 이렇게 나누는가

- 워드가 잘하는 것(저널 템플릿, 그림 배치, 변경 내용 추적, 공저자 공유)은 다시 만들지 않는다.
- 아테네움이 잘할 수 있는 것은 **읽은 것과 쓰는 것을 잇는 일**이다. 이미 논문별 메모·질문이 저장돼 있고, 번역문 문장마다 원문 문장·쪽 번호가 연결돼 있다(`.번역.정렬.json`).
- 왕복(round-trip)은 하지 않는다. 그림·수식·변경 추적이 왕복에서 깨지기 때문이다. 한 방향으로만 넘긴다.

## 데이터

`MAENG_paper\원고\<원고이름>.json` (한 원고 = 한 파일, 사람이 읽을 수 있는 JSON)

```
{
  "title": "Ta-2.5W 합금의 극저온 절삭",
  "meta": {"journal": "", "kind": "research|review", "lang": "ko|en"},
  "idea":    {"question": "", "novelty": "", "related": [{openalex_id, title, why}]},
  "cards":   [{"id", "text", "note", "tag",
               "source": {"file": "2023_JMP_Wang_....pdf", "sent": "s412", "page": 7}}],
  "outline": [{"id", "level": 1|2, "heading": "", "claim": "",
               "cards": ["c3","c7"], "draft": "", "status": "todo|drafted|done"}],
  "refs":    [{"file", "doi", "bib"}],
  "versions":[{"t", "outline_snapshot"}]
}
```

카드의 `source`가 핵심이다. 근거 카드를 누르면 그 논문의 그 문장으로 바로 이동한다(읽기 화면의 문장 번호 정렬표 재사용).

## 화면

홈 상단에 **원고** 탭을 추가한다. 3단 구성:

| 왼쪽 | 가운데 | 오른쪽 |
|---|---|---|
| 개요 트리 (절·문단, 상태 표시) | 선택한 문단: 주장 한 줄 → 붙인 근거 카드 → 초안 편집기 | 근거 카드 서랍 / 내 논문에서 찾기 |

읽기 화면 드래그 툴바에 **"원고에 담기"** 를 추가한다. 누르면 선택 구절이 카드가 되고 출처(파일·문장 번호·쪽)가 자동으로 붙는다.

## Claude 기능 (모두 문단 단위, 구독 토큰)

- **아이디어 검토**: 질문 → OpenAlex 스마트 탐색 → 이미 있는 연구·빈틈 정리, 신규성 의견.
- **문단 초안**: `주장 + 붙인 카드들` → 학술 문체 한 문단. 카드에 없는 사실은 쓰지 않는다(근거 없는 문장 금지).
- **문단 손질**: 다시 쓰기 / 줄이기 / 영문화 / 쉬운 말로.
- **개요 검토**: 논리 흐름, 근거 없는 주장, 중복, 빠진 절.
- **원고 점검**: 그림·표 번호와 본문 언급 대조, 분량, 같은 말 반복.

## 한국어 초안 → 영문 원고 (사용자 작업 방식, 2026-09-04 확정)

사용자는 **한국어로 쓰고 마지막에 영어로 바꾼다.** 그래서 영문화는 곁다리가 아니라 하나의 단계로 만든다.

- **용어집이 핵심 이점**: 근거 카드는 영어 논문에서 왔으므로, 한국어 초안에 쓴 용어의 원어를 이미 알고 있다.
  카드 출처 논문들에서 실제로 쓰이는 표기를 모아 원고별 용어집(`구성인선 → built-up edge (BUE)`)을 자동으로 만들고,
  영문화할 때 그 표기를 강제한다. 번역기가 제멋대로 고르는 동의어(예: chip formation vs chip generation) 문제가 사라진다.
- **절 단위로 영문화**한다. 문단 하나씩 하면 앞뒤 문맥과 시제가 어긋난다.
- **학술 문체 규칙**을 프롬프트에 고정한다: 방법·결과는 과거형, 일반 사실은 현재형, 1인칭 남용 금지,
  같은 개념은 같은 단어로, 한국어투 직역 금지.
- **양쪽 보기**: 한국어 원고와 영문 원고를 나란히 두고 문단끼리 짝지어 본다. 읽기 화면의 요약↔번역 탭 구조를 그대로 쓴다.
  한국어판은 지우지 않고 남긴다(공저자 설명·발표 자료에 쓰임).
- **내보내기는 두 가지**: 투고용 영문 .docx, 필요하면 한국어 .docx.

## 인용·참고문헌

카드 출처 논문 → `tags.json`의 DOI → Crossref 서지 → 본문 `[n]` 자동 번호 + 참고문헌 목록 생성.
저널 형식은 나중에 선택지로. 우선 BibTeX와 번호식(Elsevier 계열) 두 가지.

## 내보내기 (.docx)

`python-docx` 사용(설치 필요). 담는 것: 제목 구조(Heading 1/2), 문단, 굵게·기울임, 인용 번호, 참고문헌 목록.
그림·수식은 `[그림 3 자리]` 표시만 두고 워드에서 채운다.
교정본 비교가 필요하면 두 판을 각각 .docx로 뽑아 워드의 문서 비교 기능을 쓴다.

## 만드는 순서

1. 원고 데이터·저장, 원고 탭 뼈대, 개요 트리
2. 읽기 화면 → "원고에 담기" (카드 생성·출처 연결)
3. 문단 초안 생성·손질 (Claude, 한국어)
4. .docx 내보내기 (python-docx 설치)
5. 영문화 단계 (용어집 + 절 단위 번역 + 양쪽 보기)
6. 인용·참고문헌 자동화
7. 아이디어 검토, 원고 점검

## 정하지 않은 것

- 투고 저널의 워드 템플릿/LaTeX 여부 (미정 → 우선 표준 스타일로 내보내고 워드에서 템플릿 적용)

## 구현 현황 (2026-09-05, 1차)

- **서버**: `manuscript.py` (server.py 가 `ms.init()` 으로 경로·Claude 함수 주입, `/ms`, `/api/ms/*`, `/fig/*` 위임). 원고 = `MAENG_paper\원고\<id>.json`, 그림 = `원고\그림\`, 내보내기 = `원고\내보내기\`.
- **화면**: `manuscript.html` — 왼쪽 개요 트리(절/소절, 상태점, 순서 이동, 개요 검토), 가운데 문단(주장·붙인 카드·초안·영문), 오른쪽 서랍(카드 / 그림 / 아이디어 / 영문 / 내보내기). 자동 저장(0.7초 디바운스), 개요가 바뀌면 이전 개요를 versions 에 20개까지.
- **읽기 화면 → 원고에 담기**: 드래그 툴바 버튼. 카드에 파일·문장 번호(sN)·쪽이 붙고, 서버가 정렬표에서 영어 원문 문장(src_text)을 채운다. 카드의 「원문 열기」는 `/view?…&sent=sN` 으로 그 문장에 표시.
- **Claude**: 초안(카드에 없는 사실 금지, 부족하면 '(근거 필요: …)', 근거 문장 끝 [cN]) / 다시 쓰기 / 줄이기 / 쉬운 말 / 영문화(용어집 강제, 과거·현재형 규칙, 앞 문단 영문 참고) / 용어집(카드의 한·영 문장 짝에서 추출) / 개요 검토(JSON issues) / 아이디어 검토(검색어 확장 → OpenAlex → 신규성 판단).
- **.docx**: python-docx 없이 zipfile 로 직접 생성 (Title/Heading1/2/Caption 스타일, 굵게·기울임, 그림 PNG 삽입 150mm 폭, [cN]→[k] 인용 번호(출처 논문 등장 순), 참고문헌 목록).
- **그림**: 절삭 도식 생성기 `schematic/turning.py` (`render(params)`, `size(params)`), 서랍의 수치 폼 → 미리보기(SVG blob) → 만들기(SVG 저장 + Edge headless PNG) → 그림 목록 자동 등록·번호, 고해상도 PNG(3배).
- **검증(2026-09-05)**: 카드 담기 → 초안(23초, 678자, [c1][c2] + 근거 필요 표시 2곳) → .docx(그림 1장, [1][2], 참고문헌 2편) 확인.

  Claude 가 `schematic/lib.py` 로 그리는 스크립트를 쓰고(`generate.py`), 실행 오류는 2회까지 되먹여 고침. 결과 SVG/PNG/스크립트를 `원고\그림\` 에 저장, 그림 목록에 자동 등록.
  **수정 요청**: 그림 아래 칸에 말로 쓰면 이전 스크립트를 고쳐 다시 그림(이력 10개, 코드 보기).

## 원고 모드 · 집중 쓰기 (2026-09-06)
사용자 지적: "한 창에 적는 칸이 크지 않다" (Word·Overleaf·Scrivener 와 비교). 두 모드로 나눔.
- **문단 모드** (기존): 주장 → 근거 카드 → 초안 → 검토 → 영문, 문단 하나씩. 초안 칸은 내용만큼 자동으로 늘어나고 최소 높이 420px.
- **원고 모드** (`renderDocMode`): 제목·초록·절 제목·문단이 위에서 아래로 이어지는 연속 편집 화면. 문단마다 자동 확장 textarea, 아래에 단어 수·카드 수·상태점·검토 지적 수·「문단 모드 →」. 절 제목도 자리에서 고침. 위에 총 단어 수, 한국어 초안/영문 전환(`ms_doclang`). 문단에 포커스하면 개요 트리의 현재 절도 따라감.
- **집중** 버튼: `body.focus` → 개요·서랍 숨기고 글을 가운데 880px 로. 글꼴 배율은 환경설정 `--ms-scale` 을 따름.
- 모드·집중 상태는 localStorage(`ms_mode`, `ms_focus`) 에 기억.
- 구현 주의: 자동 확장(`autogrow`)은 폭이 0 인 상태(숨은 탭·접힌 창)에서 재면 한 글자씩 줄바꿈되어 수만 px 높이가 나오므로 `clientWidth < 80` 이면 건너뛰고, resize·visibilitychange·집중 전환·`--ms-scale` 변경(html style 감시) 때 `refitAll` 로 다시 맞춘다.
